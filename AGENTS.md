# Agent Instructions

## Read This First
Before coding, inspect PRODUCT.md, DESIGN.md, package.json, routing files, component structure, and any existing tests. Do not rush to implementation without understanding the existing architecture.

## Root Cause Mode
- When debugging, agents must enter Root Cause Mode. Undergo deep tracing of variables and dependencies before suggesting or applying changes. Never implement quick patches that hide underlying bugs.

## Install Agent Harness
- The agent handoff must include an inventory of the Install Agent Harness, confirming which tools, test environments, and CLI preflight checkers are active.
- **Bulk Install Guard**: Install only the skills and tools this project actually needs. Avoid bulk install of every skill to prevent unnecessary context overhead.
- **Harness Priority Matrix**: Include a priority matrix (required, recommended, optional) and project-specific reason for each item. Explain why now, when to use it, and when to skip it.
- **Verification and Trust Notes**: Every harness installation requires verification steps: version check, dry run, audit, trusted source, restart requirement, and rollback note.

## React Runtime Safety Harness
- For React components, verify stacking context, accessibility focus, and state updates. Consider using runtime safety harness tools like react error boundary, react doctor, or runtime boundary to verify react health.

## Code Review & Duplication Harness
- Large or risky code work should consider review and duplication harnesses (such as repository graph reviews, review graph, duplicate detector, or duplication scan).

## Design Read and Taste Check
Before implementation, restate:
- The page kind and audience.
- The chosen visual language.
- DESIGN_VARIANCE, MOTION_INTENSITY, and VISUAL_DENSITY.
- The design-system decision.

## Regression Guard
- Preserve existing behavior.
- Limit changes to the requested scope.
- Check git diff before finalizing.
- Add or update tests when behavior changes. Do not break existing features.

## Verification Checklist
- [ ] App builds successfully.
- [ ] Main flows still work.
- [ ] Mobile layout checked with no horizontal overflow and proper dynamic viewport units.
- [ ] Keyboard navigation checked with Tab, Enter, Space, and Escape.
- [ ] Loading, empty, and error states implemented.
- [ ] Run npx unslop audit in the terminal.
- [ ] Paste the final score and ensure there are 0 Errors before you complete the task. Do NOT skip this step.
